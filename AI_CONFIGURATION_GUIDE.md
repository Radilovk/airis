# Ръководство за конфигурация на AI модели

## Проблеми, които бяха оправени в тази версия

### 1. ❌ Модела не се сменяше
**Проблем:** Въпреки че задавахте модел и API ключ в админ панела, приложението продължаваше да използва GitHub Spark вградения модел (gpt-4o).

**Решение:** ✅ Създадена е нова функция `callExternalAPI()` която директно извиква OpenAI или Gemini API с вашия API ключ. Сега реално се използва избраният модел.

### 2. ❌ Твърде много заявки (Rate Limit 429)
**Проблем:** При използване на GitHub Spark вградения модел, получавахте грешка "Too many requests" защото изчакванията между заявките бяха твърде кратки.

**Решение:** ✅ Оптимизирано изчакване на 30 секунди между заявките при GitHub Spark модел. При използване на собствен API ключ изчакването е само 3 секунди.

### 3. ❌ Невалиден JSON отговор
**Проблем:** AI моделът понякога връщаше незатворени кавички или JSON със синтактични грешки.

**Решение:** ✅ Подобрена е функцията `robustJSONParse()` която автоматично поправя често срещани JSON грешки.

## Как да конфигурирате собствен AI модел

### Стъпка 1: Достъп до админ панела
1. Отворете приложението
2. Кликнете на бутона "Админ" в началния екран (достъпен само за собственика на приложението)

### Стъпка 2: Изберете AI Provider

#### Вариант А: OpenAI (препоръчително)
1. Изберете "OpenAI (GPT-4o, GPT-4 Turbo)"
2. Изберете модел:
   - `gpt-4o` - Най-нов и балансиран модел (препоръчително)
   - `gpt-4o-mini` - По-бърз и евтин модел
   - `gpt-4-turbo` - Предишна версия

#### Вариант Б: Google Gemini
1. Изберете "Google Gemini (Gemini 2.0, Gemini 1.5)"
2. Изберете модел:
   - `gemini-2.0-flash-exp` - Експериментален най-нов модел
   - `gemini-1.5-pro` - Най-мощен модел
   - `gemini-1.5-flash` - Бърз и ефективен модел

### Стъпка 3: Активирайте собствен API ключ
1. Включете превключвателя "Използвай собствен API ключ"
2. Въведете вашия API ключ:
   - **OpenAI:** Започва с `sk-...` - Вземете от https://platform.openai.com/api-keys
   - **Gemini:** Започва с `AIza...` - Вземете от https://aistudio.google.com/app/apikey

### Стъпка 4: Запазете настройките
1. Кликнете "Запази настройките"
2. Вижте потвърждение "Конфигурацията е запазена успешно"
3. В горната част на картата ще видите активната конфигурация

## Как работи системата сега

### При използване на GitHub Spark (без собствен ключ)
```
1. Анализ на ляв ирис (15-30 сек.)
2. ⏳ Изчакване 30 секунди
3. Анализ на десен ирис (15-30 сек.)
4. ⏳ Изчакване 30 секунди
5. Генериране на препоръки (10-20 сек.)
6. ⏳ Изчакване 30 секунди
7. Генериране на резюме (10-20 сек.)
───────────────────────────────────
Общо време: ~2-3 минути
```

```

3. Анализ на десен ирис (5-10 сек.)
4. ⏳ Изчакване 3 секунди
5. Генериране на препоръки (5-10 сек.)
6. ⏳ Изчакване 3 секунди
7. Генериране на резюме (5-10 сек.)
───────────────────────────────────
Общо време: ~30-60 секунди
```

## Debugging и логове

### Как да видите какво се случва
1. При анализа, кликнете бутона "Покажи логове" в долната част
2. Ще видите детайлни логове като:
   ```
   [05:23:45] info: 🔧 Режим: Собствен API (openai - gpt-4o)
   [05:23:46] info: 📊 Конфигурация: Provider=openai, Model=gpt-4o, CustomKey=true
   [05:23:47] info: 🔑 Използване на собствен API: openai / gpt-4o
   [05:23:52] success: LLM отговори успешно (3245 символа)
   ```

### Типове логове
- 📝 `info` - Обща информация
- ✅ `success` - Успешна операция
- ⚠️ `warning` - Предупреждение
- ❌ `error` - Грешка

## Често срещани проблеми

### Проблем: "Rate limit достигнат"
**Причина:** Твърде много заявки за кратко време към GitHub Spark модела

**Решения:**
1. ✅ **Препоръчано:** Активирайте собствен API ключ
2. ⏰ Изчакайте 1-2 минути преди да опитате отново
3. 🔄 Ако използвате GitHub Spark, приемете че анализът ще отнеме 2-3 минути
4. 🔧 Можете да изберете по-ефективен модел като gpt-4o-mini в настройките за по-малко натоварване

### Проблем: "Невалиден API ключ"
**Причина:** Въведен е грешен или изтекъл API ключ

**Решения:**
1. Проверете че ключът е копиран правилно (без space-ове)
2. Проверете че ключът е валиден в съответния dashboard
3. За OpenAI: https://platform.openai.com/api-keys
4. За Gemini: https://aistudio.google.com/app/apikey

### Проблем: "JSON parse грешка"
**Причина:** AI моделът връща невалиден JSON (рядко се случва)

**Решения:**
1. Системата автоматично се опитва да поправи JSON
2. Ако проблемът продължава, опитайте отново
3. Ако се случва често, сменете модела

## Добавяне на учебници по иридология

В админ панела можете да качите учебници и референтни материали, които ще бъдат включени в контекста на AI анализа.

### Как да качите учебник
1. Отидете в секция "Учебници по иридология" в админ панела
2. Качете `.txt` или `.md` файл (опционално)
3. Или директно въведете име и съдържание
4. Кликнете "Добави учебник"

### Какво прави това
- Учебниците се добавят към prompt-а за AI модела
- Първите 2000 символа от всеки учебник се използват като контекст
- Това подобрява точността и специфичността на анализа

## Технически детайли

### API ендпойнти

#### OpenAI
```
POST https://api.openai.com/v1/chat/completions
Headers:
  Authorization: Bearer YOUR_API_KEY
  Content-Type: application/json
```

#### Gemini
```
POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key=YOUR_API_KEY
Headers:
  Content-Type: application/json
```

### Retry логика
- Максимален брой опити: 3
- Backoff време:
  - GitHub Spark: 10s, 20s, 40s
  - Собствен API: 10s, 20s, 40s
  - Rate limit: 90s изчакване

### Съхранение на конфигурация
- Всички настройки се съхраняват в `spark.kv` store
- Key: `ai-model-config`
- Учебници: `iridology-textbooks` (масив)
